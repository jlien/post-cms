# Task: Build the Post-CMS Publishing Stack prototype (v0.1)

You are building a working prototype of the architecture described below. The repo is ~/Eng/post-cms (skeleton dirs already created: content/posts, crates/build/src, crates/server/src, mcp, ci, templates, agents).

## Architecture summary

A CMS-free publishing stack: content lives as structured files in git; a build step renders static HTML; a tiny Rust origin serves it; a CDN (simulated locally) fronts it; an MCP tool server lets an AI agent do all content operations.

## Deliverables

### 1. Content format (content/posts/<slug>/)
- `meta.yaml`: title, slug, tags (list), lang, published (bool), date, description
- `index.mdx`: body (treat MDX as markdown; no JSX compilation needed — plain markdown is fine)
- Seed with 3 example posts (a welcome post, a post about this architecture, a post about static-first rendering)

### 2. Static build pipeline — Rust (crates/build)
- Reads all content dirs, parses YAML frontmatter + markdown body
- Renders to `dist/`: one HTML file per post, an index page listing posts (sorted by date desc), RSS 2.0 feed (dist/rss.xml), sitemap.xml, robots.txt
- Use rust crates: serde, serde_yaml, pulldown-cmark, tera (templates), chrono, anyhow
- Templates in templates/ (base.html, post.html, index.html) — dark clean styling, no external assets (system fonts, inline CSS), so the site is fully self-contained
- Output must include proper Cache-Control guidance comment and content-hash CSS inline
- `cargo run -p build` produces dist/ — verify with actual file checks

### 3. Origin server — Rust (crates/server)
- Axum-based; serves files from dist/ with correct MIME types
- Routes: / (index), /posts/<slug>, /rss.xml, /sitemap.xml, /robots.txt, /health (returns JSON {"status":"ok"})
- Sets Cache-Control headers: HTML → public, max-age=0, s-maxage=86400, stale-while-revalidate=604800; rss/sitemap → s-maxage=3600
- 404 page (dist/404.html — also generated by build)
- Port 8787 (configurable via PORT env)

### 4. MCP tool server (mcp/server.py)
- stdio JSON-RPC 2.0 implementing MCP protocol (initialize, tools/list, tools/call) — implement the protocol directly with stdlib only (no external deps), or use uv-managed mcp package if simpler; stdlib preferred
- Tools:
  - list_posts(status: "all"|"published"|"draft") → JSON summary
  - get_post(slug) → full content + meta
  - create_draft(slug, title, body, tags, description) → writes meta.yaml (published: false) + index.mdx, returns path
  - update_post(slug, title?, body?, tags?, published?, description?) → edits fields, returns diff summary
  - build_site() → shells out to `cargo run -p build`, returns output tail
  - publish_status() → live/pending/scheduled counts + lists
- All mutations are git commits (run `git add` + `git commit -m "..."` via subprocess; skip if not a git repo — just write files then)
- Include a self-test mode: `python3 mcp/server.py --self-test` that exercises each tool via the protocol handlers and prints results

### 5. Deploy + CDN purge (ci/deploy.sh, ci/purge.sh)
- deploy.sh: builds, rsyncs dist/ to a configurable target dir (env ORIGIN_TARGET, default ./deploy-target), prints done
- purge.sh: stub CDN purge — writes a timestamped log line to ci/purge.log and prints "purged". Include a commented Cloudflare API curl example for production
- ci/build.sh: cargo build + run build crate

### 6. Repo hygiene
- git init, .gitignore (target/, dist/, deploy-target/), root README.md documenting: architecture diagram (ASCII), how to build, serve, run MCP self-test, deploy
- agents/CONVENTIONS.md: how an agent should operate this stack (draft → preview → publish flow, the publish gate rule: never merge to production without explicit confirm)
- One initial git commit of everything
